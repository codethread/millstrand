# Weaver runtime delta for deps-native spool dependencies

**Document ID:** `DELTA-DnsRuntime-001`
**Root spec:** [daemon-runtime.md](../../../specs/daemon-runtime.md) (`SPEC-004`)
**Feature:** [../proposal.md](../proposal.md) (`PROP-Dns-001`)
**Status:** Proposed
**Last Updated:** 2026-08-29

This delta replaces `SPEC-004.C39-C50b` and `SPEC-004.C91-C94a`. It preserves `SPEC-004.C113-C123` without weakening or restating their ownership.

## DELTA-DnsRuntime-001.P1 Runtime dependency model

- **DELTA-DnsRuntime-001.CC1 (replaces SPEC-004.C39-C41):** `millstrand.api.runtime.alpha` remains the blessed explicit-runtime API for module declaration, refresh, planning, status, code reload, and Var resolution. A selected workspace contains required `deps.edn`, optional `deps.local.edn`, shared `init.clj`, optional `init.local.clj`, configuration, and workspace-relative module files. `spools.edn`, `spools.local.edn`, release markers, family/root approval, and structural dependency editors have no runtime role. The public removals remain exactly those in `PROP-Dns-001.S6` and the bounded alpha exception owned by the SPEC-003 and SPEC-005 deltas; this clause adds none.
- **DELTA-DnsRuntime-001.CC2 (replaces SPEC-004.C42-C44b; source order):** The basis boundary invokes `clojure.tools.deps/create-basis` with the tools.deps root source, `:user nil`, the parsed `<selected-workspace>/deps.edn` as the project source, and the parsed `<selected-workspace>/deps.local.edn` as the later extra source when that readable regular file exists. It does not read the global user source or an enclosing project's project source. `deps.edn` is required. An absent `deps.local.edn` contributes nothing. Relative paths in both sources resolve from the selected workspace under ordinary tools.deps rules.
- **DELTA-DnsRuntime-001.CC3 (alias and source composition):** After source composition, the basis boundary selects `:millstrand/weaver` when declared and then `:millstrand/local` when declared. An absent alias is not selected and is not an error. tools.deps owns composition: project `:deps`, `:replace-deps`, `:paths`, and `:replace-paths` apply before the later extra source; the extra source's top-level `:deps` and `:paths` replace collisions from the project source; resolve and classpath args apply afterward. Within the same map-valued alias key, later local lib values win; path values concatenate distinctly in alias order. Across different keys, tools.deps precedence remains unchanged: `:replace-deps` wins over `:deps`, `:replace-paths` follows `:paths`, and `:override-deps` wins regardless of which selected alias supplied it. Millstrand performs no parallel merge or coordinate translation.
- **DELTA-DnsRuntime-001.CC4 (reserved runtime coordinate):** Before `create-basis`, the boundary rejects `io.millstrand/millstrand` anywhere either workspace source could contribute it to the selected launch, including top-level dependency maps and the two selected alias maps. Mill then supplies exactly one paired `io.millstrand/millstrand` coordinate from its resolved source as reserved launch data. The reserved value participates after workspace sources and selected aliases and cannot be overridden. The loud failure is `reserved dependency io.millstrand/millstrand is supplied by Mill`; it includes the resolved source path and offending value.
- **DELTA-DnsRuntime-001.CC5 (boundary parsing and resolution):** The boundary reads and parses each present dependency file once into a tools.deps map, validates the required canonical file and reserved-coordinate rule, then passes those parsed values inward. Missing, unreadable, non-regular, non-map, or malformed `deps.edn` data fails with `:status :invalid-dependency-config`, `:stage :deps-read`, `:source-path`, `:message`, `:cause`, and `:coordinate nil`. Equivalent faults in a present local overlay use its resolved path. Resolution failure uses `:stage :deps-resolve`, preserves the original cause, and includes `:coordinate {:lib symbol :value edn-value}` plus the source path when tools.deps identifies one offending coordinate; otherwise `:coordinate nil` is the explicit unresolved-coordinate outcome. The boundary does not catch and continue, retry, use a default basis, consult a legacy manifest, or reparse trusted interior values.

## DELTA-DnsRuntime-001.P2 Fingerprint and generation classloader

- **DELTA-DnsRuntime-001.CC6 (basis fingerprint; resolves PROP-Dns-001.Q1):** The immutable generation fingerprint is `sha256:<digest>`, where `<digest>` is 64 lowercase hexadecimal digits over the UTF-8 bytes of one canonical EDN value. That value has exactly `:sources`, `:aliases`, `:reserved-deps`, and `:basis`: `:sources` is the ordered vector of `{:kind :project|:extra :deps parsed-map}` entries actually consulted; `:aliases` is the ordered vector of selected alias keywords; `:reserved-deps` is the one-entry map containing the paired runtime coordinate; and `:basis` is exactly `{:libs (:libs basis) :classpath-roots (vec (:classpath-roots basis)) :argmap (:argmap basis)}` from the completed `create-basis` result. Resolved source paths remain diagnostic data and are not fingerprint input, so a fresh probe using copied configuration has the same identity. Canonical EDN recursively orders every map entry and set member by the UTF-8 byte ordering of that item's canonical EDN representation, preserves sequential order, uses ordinary tagged-independent EDN scalar printing, and has no metadata or reader-eval forms. The encoder rejects values outside that closed EDN domain. It emits no whitespace beyond the delimiters and one ASCII space between adjacent collection items. This digest is identity, not a cache key or compatibility version. The running runtime stores the fingerprint once and never mutates it.
- **DELTA-DnsRuntime-001.CC7 (fingerprint ownership):** `:millstrand.core.specs/basis-fingerprint` owns the internal `sha256:<64 lowercase hexadecimal digits>` string and `:millstrand.api.runtime.alpha/basis-fingerprint` is its public alias. `:millstrand.core.specs/generation-basis` owns the parsed sources and their resolved paths, selected aliases, reserved coordinate, basis projection, fingerprint, and classloader identity retained by the runtime. The basis constructor consults both core specs before startup activation; `runtime/status` consults the public alias and `::status-result` before returning data. Their owning docstrings are the generation-basis constructor and `millstrand.api.runtime.alpha/status`; their contract-doc reference is CC6-CC7. Invalid constructed values fail startup loudly; trusted interior consumers do not reparse dependency files or invent fallback values.
- **DELTA-DnsRuntime-001.CC8 (replaces SPEC-004.C44c-C44f and C47-C50b):** One Weaver generation has one classloader built from the completed tools.deps basis. All shared and personal libraries, Maven artifacts, Git roots, `:deps/root` roots, local roots, exclusions, paths, and classpath overrides use their ordinary tools.deps resolution in that classloader. Module evaluation, `resolve-var`, event handlers, scheduled handlers, lifecycle callables, and registry dispatch resolve through it. There is no dynamic spool classloader, approved-root acquisition, per-module classloader, live coordinate addition, family/root source resolution, or unloading. `resolve-var` retains public input `::resolvable-symbol` and return `(s/nilable var?)`; its function boundary consults both through its `s/fdef`, and its docstring cites this clause. `reload-code!` retains public input spec `::root-lib`, reshapes it to accept a lib present in the running basis, and returns the reshaped `::reload-code-result` without root/sync fields; its function boundary consults its `s/fdef` and validates the result before return, and its docstring cites this clause. Unknown libs and non-source-backed reload targets fail loudly. Neither function reads dependency files, resolves coordinates, or changes the classpath.

## DELTA-DnsRuntime-001.P3 Refresh, plan, and status

- **DELTA-DnsRuntime-001.CC9 (replaces SPEC-004.C45-C46 dependency guards):** A module declaration keeps only its owner, one `:ns` or workspace-relative `:file`, optional `:load :image`, `:after`, and `:required?`. It carries no `:spools` prerequisite. Public `::module-opts` owns this closed input and `::module-declaration` owns the normalized result within `::module-result`; `module!` consults the input spec before collection and validates its result before return, and its docstring cites this clause. Dependency presence never activates code. Startup and refresh collect `init.clj` then `init.local.clj`; a later declaration of the same owner replaces the earlier declaration. Owner-complete authoring, candidate validation, atomic publication, lifecycle reconciliation, omission, source/image behavior, and retained declaration records continue under their existing contracts.
- **DELTA-DnsRuntime-001.CC10 (refresh-before-activation boundary):** `runtime/refresh!` parses and resolves one candidate generation basis through CC2-CC6 before evaluating either startup file or any module source. It compares the candidate fingerprint with the immutable running fingerprint. Equality permits the existing configuration/module refresh against the running classloader. A valid difference returns `{:status :restart-required :reason :dependency-basis-changed :basis {:running-fingerprint running :candidate-fingerprint candidate}}`; it publishes no registry, declaration record, module, lifecycle, resource, startup, or configuration change. Refresh never installs the candidate classpath. There is no fallback comparison, retry, partial activation, or speculative recovery.
- **DELTA-DnsRuntime-001.CC11 (dependency read/resolve results; resolves the runtime part of PROP-Dns-001.Q2):** A failed candidate read returns `{:status :invalid-dependency-config :stage :deps-read :source-path path :message string :cause string :coordinate nil}`. A failed candidate resolution has the same status and uses `:stage :deps-resolve`; `:coordinate` is either `{:lib symbol :value edn-value}` with the resolved source path that supplied it, or nil when the resolver cannot isolate one coordinate. The original parser or resolver cause is required and non-blank. Both outcomes leave every running value and pending activation edit untouched. `:millstrand.core.specs/dependency-diagnostic` owns the internal closed shape and `:millstrand.api.runtime.alpha/dependency-diagnostic` is its public alias included by public `::refresh-result`; public `::basis-change` owns the closed `:basis` pair in the restart-required alternative. `runtime/refresh!` validates its result against `::refresh-result` before return. Its docstring owns the public Clojure promise and cites CC10-CC11. Missing paths or causes, unknown stages, malformed coordinates, and contradictory status/stage data fail loudly.
- **DELTA-DnsRuntime-001.CC12 (plan and status projections):** `plan` previews configuration and module publication only after the candidate basis passes CC10; on a changed basis it returns the same validated restart-required result and stages no activation. `status` reports modules, resources, loaded namespaces, `:basis-fingerprint`, and `:last-refresh`; it has no families, roots, sync, acquisition, release-marker, or pending-generation fields. Public `::plan-result` owns the plan shape and public `::status-result` owns the status shape. `plan` and `status` validate those specs before returning. Their docstrings cite this clause. Refresh and module results use `::refresh-result` and `::module-result` and contain no removed root/sync fields.

## DELTA-DnsRuntime-001.P4 Removed acquisition and retained continuity

- **DELTA-DnsRuntime-001.CC13 (replaces SPEC-004.C91-C94a):** tools.deps alone reads and resolves workspace coordinates and materializes Git and Maven dependencies. Millstrand owns no Git cache layout, fetch ladder, tag verification, manifest validation, Maven override translation, root prerequisite computation, per-root acquisition outcome, or dynamic URL addition. Ordinary tools.deps diagnostics are preserved through CC5 and CC11. No compatibility namespace, manifest parser, or acquisition result remains as an alias.
- **DELTA-DnsRuntime-001.CC14 (retains SPEC-004.C113-C123):** Weaver generation identity, restart records, fresh-generation probe ordering, admission, one-send delivery, process custody, owner reconciliation, interruption outcomes, scope, and coverage remain exactly governed by `SPEC-004.C113-C123`. The fresh probe and replacement each build one independent generation basis and classloader through CC2-CC8. A dependency failure is visible at `deps-read` or `deps-resolve`; it does not trigger a retry or fallback basis. A failed probe retains and continues serving the admitted old generation. After cutover, a failed replacement remains failed and never readmits the old generation. Custodied work and all retained continuity cross a successful dependency-driven replacement unchanged.
