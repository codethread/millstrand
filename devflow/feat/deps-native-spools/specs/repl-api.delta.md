# REPL API delta: deps-native spool dependencies

**Delta ID:** `DELTA-Dns-Repl-001`
**Target:** [SPEC-003](../../../specs/repl-api.md)
**Authority:** [PROP-Dns-001](../proposal.md)
**Status:** Proposed; apply only with the implementing change

This delta replaces `SPEC-003.C17`, `C18`, `C19`, `C24`, `P5`, and `C28`–`C32`. `C24` is an inseparable adjacent clause because it gives `reload-code!` its current root-sync contract. Clauses not named here remain unchanged. In particular, this delta does not alter the restart and custody contracts in `SPEC-003.P4b` or `SPEC-004.C113`–`C123`.

## Replacement clauses

- **DELTA-Dns-Repl-001.C1 (replaces SPEC-003.C17):** `millstrand.api.runtime.alpha` exposes explicit module declaration, owner-complete activation and refresh, module/configuration planning and status, the advanced code-only `reload-code!` seam, runtime-local `spool-state`, generation-classloader `resolve-var`, and the existing runtime clock functions. It exposes no dependency editor, package operation, approval projection, acquisition result, or live classpath mutation. The namespace docstring names these functions and points to `SPEC-003.P5`; every function docstring names its public input and result specs as required by C5–C12 below.

- **DELTA-Dns-Repl-001.C2 (replaces SPEC-003.C18):** Every `millstrand.api.runtime.alpha` helper that acts on a runtime takes that runtime first. Trusted `init.clj`, `init.local.clj`, module code, and in-process tools capture the active runtime once with `millstrand.api.current.alpha/runtime` and thread it explicitly. Connected clients do not route these calls through `millstrand.api.runtime.alpha`. The existing `:millstrand.api.current.alpha/runtime` and `:millstrand.api.current.alpha/runtime-or-nil` specs and function docstrings continue to own and document that capture boundary.

- **DELTA-Dns-Repl-001.C3 (replaces SPEC-003.C19 and its compatibility exception):** The namespace tiers and accretion rule remain unchanged. This feature adds one bounded pre-v1 exception under TEN-000@1: remove `millstrand.api.runtime.alpha/approved`, `declared`, `release-marker`, `upsert-spool-entry!`, and `remove-spool-entry!`, their public specs and result shapes, and the `module!` option `:spools`. Remove the complete `strand spool` operation family under SPEC-002. No alias, deprecated forwarding Var, parallel namespace, feature probe, fallback parser, or compatibility grammar remains. The exception covers exactly those names and the one option; another public removal requires another root-spec decision.

- **DELTA-Dns-Repl-001.C4 (replaces SPEC-003.C24):** `(runtime/reload-code! runtime lib)` accepts a qualified library symbol present in the running generation's tools.deps basis. The input retains the public `:millstrand.api.runtime.alpha/root-lib` spec name with basis-lib semantics, and the returned closed map conforms to `:millstrand.api.runtime.alpha/reload-code-result`. The result contains exactly `:lib`, `:status`, and `:namespaces`; `:status` is `:reloaded` or `:unchanged`, and `:namespaces` is a vector of qualified namespace symbols in reload order. The function resolves source-backed classpath entries already recorded for that library, reloads their loaded namespaces in dependency order through the one generation classloader, and never resolves, adds, removes, or replaces a coordinate. An absent library, a library without a source-backed classpath entry, a malformed input, or a reload failure throws `ExceptionInfo` with the library and failing stage. The function and `s/fdef` consult the two named specs at call and return boundaries, and its docstring cites this clause. Publication and lifecycle reconciliation remain the job of `refresh!`.

## Replacement for SPEC-003.P5: runtime workspace helpers

- **DELTA-Dns-Repl-001.C5 (activation files):** `<selected-workspace>/init.clj` is the shared activation file. Optional `<selected-workspace>/init.local.clj` is read second and may replace a shared module declaration by declaring the same owner key. Both files contain ordinary trusted Clojure and call `(runtime/module! runtime owner opts)` explicitly; dependency presence never activates code. Startup and a full `refresh!` evaluate each present file in that order. An absent file contributes no declarations for its layer. An unreadable file, an evaluation error, or an invalid declaration fails at the activation-file boundary with the resolved path and original cause. Activation-file outcomes conform to `:millstrand.api.runtime.alpha/activation-file-result`, a closed map containing exactly `:path`, `:layer` (`:shared` or `:local`), and `:status` (`:loaded` or `:absent`). The runtime API namespace docstring and `refresh!`/`plan` docstrings cite this clause and that spec.

- **DELTA-Dns-Repl-001.C6 (module declaration):** `(runtime/module! runtime owner opts)` declares one owner under a stable keyword. `opts` is closed by `:millstrand.api.runtime.alpha/module-opts` to exactly one of `:ns` or selected-workspace-relative `:file`, plus optional `:load :image`, `:after`, and `:required?`; `:spools`, callbacks, and unknown keys are invalid. `:load :image` is valid only with `:ns`. The normalized declaration conforms to `:millstrand.api.runtime.alpha/module-declaration`, and the staged or refreshed return conforms to `:millstrand.api.runtime.alpha/module-result`. `module!` validates owner, options, normalized declaration, and return value through those specs, and its docstring cites them and this clause. File targets may not escape the selected workspace. Namespace targets resolve through the running generation classloader. Image mode uses only a current retained declaration record. Missing, stale, foreign, or malformed records fail as that module's evaluation outcome.

- **DELTA-Dns-Repl-001.C7 (owner-complete publication):** Each successful module source evaluation collects the typed `use-*!` selections, combined `def*!` selections, open-kind declarations, and lifecycle declarations for that owner. The collected set is complete: publication atomically replaces that owner's prior registry partitions and lifecycle declarations, so omission retracts prior entries. The collected value conforms to `:millstrand.api.runtime.alpha/module-collection`; the candidate module outcome conforms to `:millstrand.api.runtime.alpha/module-outcome`. Collection, candidate assembly, and publication consult those specs at their boundaries. The `collect-entry!`, `collect-kind!`, authoring-form, `module!`, `plan`, and `refresh!` docstrings cite this owner-complete contract. A failed source evaluation or invalid collection publishes nothing and leaves the owner's current image unchanged.

- **DELTA-Dns-Repl-001.C8 (live boundary):** A full `(runtime/refresh! runtime)` re-reads both activation files and reconciles source, module graph, owner-complete contributions, and lifecycle resources already available to the running generation. Live changes are edits to a declared `:ns` or `:file` source, module additions or omissions, `:after` or `:required?` changes, owner-complete selection changes, and lifecycle declaration changes. Targeted refresh retains the existing `{:only [owner ...]}` grammar, includes affected dependants, does not re-read activation files, and cannot remove an unselected owner. Neither arity acquires a library or changes a classpath.

- **DELTA-Dns-Repl-001.C9 (basis wire vocabulary; resolves PROP-Dns-001.Q2 for the REPL API):** `:millstrand.api.runtime.alpha/basis-fingerprint` is the public alias of `:millstrand.core.specs/basis-fingerprint` and accepts the `sha256:<64 lowercase hexadecimal digits>` encoding fixed by `DELTA-DnsRuntime-001.CC6`. `:millstrand.api.runtime.alpha/basis-change` is the public alias of `:millstrand.core.specs/basis-change` and owns exactly `{:running-fingerprint F :candidate-fingerprint F2}`, where both values conform to `basis-fingerprint` and differ. `:millstrand.api.runtime.alpha/dependency-diagnostic` is the public alias of `:millstrand.core.specs/dependency-diagnostic` and owns exactly `{:status :invalid-dependency-config :stage S :source-path P :message M :cause C :coordinate X}`. `S` is `:deps-read` or `:deps-resolve`; `P`, `M`, and `C` are non-blank strings; and `X` is nil or exactly `{:lib qualified-symbol :value edn-value}`. Nil is the explicit outcome when tools.deps cannot isolate one coordinate. These are the only REPL-facing basis and dependency-failure field names. The public aliases, `refresh-result`, `plan-result`, and `status-result` are registered in `millstrand.api.runtime.alpha`, are cited by the `refresh!`, `plan`, and `status` docstrings, and are consulted when each candidate basis and public result is assembled.

- **DELTA-Dns-Repl-001.C10 (`refresh!`):** Before evaluating either activation file or module source, full refresh composes and resolves a candidate basis only for comparison with the running fingerprint. A difference returns exactly `{:status :restart-required :reason :dependency-basis-changed :basis B}`, where `B` conforms to `basis-change`; no pending activation or source change becomes visible. Invalid dependency data returns the exact `dependency-diagnostic` map from C9 at top level. It does not wrap that map or replace its preserved cause. Current-basis refresh retains the existing `:applied`, `:partial`, and `:unchanged` module/lifecycle outcome data and removes every root, family, sync, acquisition, and pending-generation field. The input conforms to `:millstrand.api.runtime.alpha/refresh-opts`, the union conforms to `:millstrand.api.runtime.alpha/refresh-result`, `refresh!` consults both at call/return boundaries, and its docstring cites C8–C10. A missing canonical `deps.edn` is an invalid `:deps-read` result naming its resolved path and remediation; it never produces a default or empty basis.

- **DELTA-Dns-Repl-001.C11 (`plan`):** `(runtime/plan runtime)` and its targeted arity perform the same reads, candidate-basis comparison, source evaluation, collection, and validation as `refresh!`, but do not publish, reconcile, mutate coordinator state, or replace retained image records. The result has the same dependency short-circuit variants as C10, and current-basis plans contain only activation-file, module, contribution, lifecycle, resource, namespace, and conflict intentions. Root-sync and acquisition fields are forbidden. Inputs conform to `:millstrand.api.runtime.alpha/refresh-opts`; output conforms to `:millstrand.api.runtime.alpha/plan-result`. `plan` consults both specs and names them with this clause in its docstring.

- **DELTA-Dns-Repl-001.C12 (`status` and `resolve-var`):** `(runtime/status runtime)` is an offline read and returns a closed `:millstrand.api.runtime.alpha/status-result` containing exactly `:basis-fingerprint`, `:modules`, `:resources`, `:loaded-namespaces`, and `:last-refresh`. Its fingerprint conforms to the public spec in C9; status does not re-read dependency files and exposes no candidate fingerprint, family, root, sync, acquisition, or pending-generation state. `(runtime/resolve-var runtime sym)` requires a qualified symbol conforming to the retained `:millstrand.api.runtime.alpha/resolvable-symbol` spec, resolves and, when needed, requires its namespace through the one generation classloader, and returns a Var or nil when that namespace defines no Var at the name. Resolution and load failures propagate with symbol and namespace context; it never searches another loader or resolves dependencies. `status` and `resolve-var` consult their named input/return specs through `s/fdef`, and both docstrings cite this clause.

- **DELTA-Dns-Repl-001.C13 (restart continuity):** A restart-required or invalid-dependency result changes no live module, registry, lifecycle, resource, retained-image, or classloader state. Taking the edited basis into use requires the replacement flow in `SPEC-004.C113`–`C123`. This API neither starts replacement nor retries an interrupted call. It preserves the restart contract's generation identity, fresh-generation probe, admission, one-send, custody, reconciliation, and no-replay boundaries unchanged.

## Replacement for SPEC-003.P8 author-side test helpers

- **DELTA-Dns-Repl-001.C14 (replaces SPEC-003.C28):** `millstrand.test.alpha` retains `with-weaver-world`, `weaver-world-fixture`, `repl!`, `spool-checkout-root`, `check-op-return!`, `await-quiescent!`, `activate-module!`, `collect-module-forms`, and the deterministic-clock helpers. `activate-module!` accepts only `:after` and `:load :image`; its existing `:millstrand.test.alpha/bare-runtime`, `module-key`, `namespace-symbol`, `module-options`, and `module-refresh-outcome` specs and docstring remain the public contract, with approval/acquisition language removed. `collect-module-forms` retains its named specs, `s/fdef`, docstring, and owner-complete unpublished result contract.

- **DELTA-Dns-Repl-001.C15 (replaces SPEC-003.C29):** `with-weaver-world` creates or accepts an isolated workspace, writes requested `config.json`, mandatory `deps.edn`, optional `deps.local.edn`, `init.clj`, optional `init.local.clj`, and workspace-relative files, then starts the unpublished runtime. Its option boundary conforms to `:millstrand.test.alpha/weaver-world-options`, and its generated-file projection conforms to `:millstrand.test.alpha/weaver-world-files`; both specs are closed, are consulted before files are written and before the context is bound, and are named by the macro and fixture docstrings. The helper never writes either removed manifest. Missing canonical `deps.edn`, malformed dependency data, startup failure, and cleanup failure retain the existing fail-loud and suppressed-cleanup behavior.

- **DELTA-Dns-Repl-001.C16 (replaces SPEC-003.C30):** `repl!`, direct authoring helpers, return checking, owner-suite coverage, real nREPL transport, and EDN-readable result rules remain unchanged. The namespace docstring describes classpath-visible modules and generation-basis fixtures, with no approval, acquisition, root-sync, or manifest terminology. Each retained helper continues to consult the named public specs and `s/fdef` contracts assigned by `SPEC-003.C28`–`C30`.

- **DELTA-Dns-Repl-001.C17 (replaces SPEC-003.C31):** The world context conforms to the closed `:millstrand.test.alpha/weaver-world-context` spec and contains exactly `:config-dir`, `:state-dir`, `:data-dir`, optional `:db-path`, `:storage`, `:source`, `:runtime`, `:metadata`, `:timeout-ms`, and `:basis-fingerprint`. `:basis-fingerprint` conforms to the runtime API spec of the same name and identifies the basis used to launch the in-process generation. `with-weaver-world`, `weaver-world-fixture`, and their docstrings name and consult this context spec.

- **DELTA-Dns-Repl-001.C18 (replaces SPEC-003.C32):** `millstrand.test.alpha/spool-checkout-root` remains the author-side helper for finding the directory checkout that backs a spool source resource on the test classpath. It returns the nearest checkout root whose `deps.edn :paths` contains the supplying classpath entry, for use as an ordinary tools.deps `:local/root`; it does not approve, activate, or write dependency data. Its input conforms to `:millstrand.test.alpha/classpath-resource`, its return conforms to `:millstrand.test.alpha/local-root`, and both arities consult those specs. The function docstring names the specs and this clause. Missing, jar-backed, and structurally unmatched resources fail loudly as before.
