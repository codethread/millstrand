## DELTA-Dsp-004.P1 Summary

Phase C retires the transitional resolution language `DELTA-Dsp-002.CC2` introduced. `runtime/module!` no longer accepts `:contribute`/`:reconcile` (`DELTA-Dsp-003.CC1`), and neither does any other authoring seam — trusted startup collection and the internal `declare-module!` refuse the keys too — so no newly authored declaration can reach the coordinator carrying an entry point and the per-key precedence rule has nothing left to arbitrate. What survives of that rule is a reader over declarations a live weaver collected before it picked this change up, and nothing else (`DELTA-Dsp-004.D3`). SPEC-004.C45 and C46 state convention resolution plainly: for every module, at every module evaluation, the coordinator resolves and root-value-validates each effective `:contribute`/`:reconcile` symbol from the public `spool` var in the module's namespace.

This is the last step of an ergonomics and ownership change, not a runtime behavior change. Contribution, publication, reconcile status branching, retained last-good resolved entry points, removal-by-omission teardown, source stamps and the `:unchanged` fast path, dependency ordering, root guards, residual and conflict reporting, and every `reload-code!` and refresh semantic are exactly as they were in Phase A (`PROP-Dsp-001.NG1`, `PROP-Dsp-001.R4`, `ADR-004.P6`). What changes is that one source of a module's entry points — the declaration — is gone, leaving the one the coordinator already consulted whenever a declaration left a field absent.

## DELTA-Dsp-004.P2 Contract changes

- **DELTA-Dsp-004.CC1 (resolution is unconditional — amends SPEC-004.C45/C46):** The coordinator consults the public `spool` var in the module's loaded namespace for every effective entry point, with no per-key precedence and no complete-declaration bypass. The transitional sentences in C45 and C46 — an explicitly declared key winning per key, the var filling only absent fields, and a complete Phase A explicit declaration neither consulting nor validating the var — are deleted. Resolution timing, the `:ns`/`:file`/image target rules, the single-`ns` requirement for `:file` targets, the authoring-forms-only behavior of a file that declares no namespace, and coordinator qualification of unqualified symbols against the declaring namespace are all unchanged (`DELTA-Dsp-002.CC1`).

- **DELTA-Dsp-004.CC2 (image mode has one entry-point source — amends SPEC-004.C45/C46):** A `:load :image` module resolves `<ns>/spool` from the already-loaded JVM image. The Phase A alternative — a loaded image namespace with no public `spool` var supplying contribution through an explicit `:contribute` — is gone. An unloaded namespace and a loaded namespace with no resolvable contribution are both that module's loud evaluation-time `:failed` outcome, on the same per-module evaluation-failure channel as a missing synced source, never a top-level `:refused` and never a throw out of `module!`, with error data naming `:module/key`, the offending `:ns`, and `:load :image`. Both carry one common message naming both requirements — load or require the namespace, and give it a public `spool` var supplying `:contribute` — because a reader who hits either branch cannot tell from the outcome which half they are missing (SPEC-004.C46). The declaration-time refusals that were never about entry points — a `:file` target under `:load` (`:allowed [:ns]`) and a non-`:image` `:load` value (`:allowed #{:image}`) — stay declaration-time refusals, and an image outcome still states `:source/status :image` and carries no source stamp in `plan` and `status` alike.

- **DELTA-Dsp-004.CC3 (retention, loud enforcement, and invariants unchanged — restates SPEC-004.C45–C46b, C70):** Retained last-good resolved entry points and their additive `status`/`plan`/refresh exposure (`DELTA-Dsp-002.CC4`), removal-by-omission reconciling through that retained set (SPEC-004.C46b), and the enumerated loud failures (`DELTA-Dsp-002.CC5`) carry over verbatim: a `spool` value that is not a map, has unknown keys, or has neither entry point; an entry-point value that is not a symbol; a symbol that does not resolve or whose var's **root value** is not a fn, checked by dereferencing the var because a Clojure Var is itself `ifn?` regardless of what it holds; and a `spool` var carrying `:contribute` while the same source load collected authoring forms, a conflict still scoped to `:contribute` so a `:reconcile`-only var composes with collected forms. An ns module with neither a `spool` var nor collected forms stays legal, and a stale `spool` var after an in-place reload keeps parity with today's symbol resolution — no var-cleanup machinery, with the pickup ladder as the documented remedy.

## DELTA-Dsp-004.P3 Design decisions

- **DELTA-Dsp-004.D1 (close the window at the declaration boundary):** The precedence rule ends for newly authored declarations because every authoring seam stops accepting the keys (`DELTA-Dsp-003.CC1`), not because resolution learned a new rule. **Rationale:** the coordinator's convention lookup is the same code path Phase A already ran for absent fields, so closing the window costs no new resolution behavior and no new failure mode. **Rejected:** keeping a resolution-side precedence rule that a freshly authored declaration could still reach, which would leave a live branch describing a contract the spec no longer states. The branch that does remain is not that rule: it reads pre-cutover graph state only, and D3 says when it goes.

- **DELTA-Dsp-004.D2 (image mode keeps its evaluation-time failure, unrelaxed):** Removing the explicit `:contribute` alternative leaves image mode with exactly one entry-point source and the same loud `:failed` outcome when it is missing. **Rationale:** `ADR-003.P9` forbids resolving the image-mode friction by relaxing a loud failure, and `DELTA-Dsp-002.D1` already accepted and named the declaration-to-evaluation locality move. **Rejected:** a silent empty contribution for a loaded image namespace with no `spool` var (`PROP-Dsp-001.NG4`).

- **DELTA-Dsp-004.D3 (retained pre-cutover graph state stays readable):** Every fresh declaration normalizer rejects the keys, while `legacy-resolved-entry-points` can still read `:contribute`/`:reconcile` from graph state already held by a live coordinator. A targeted refresh or targeted plan that would evaluate any such retained declaration is refused before sync, evaluation, or publication with ex-data naming the selected modules, every affected retained module, and their retained entry points; prior live state remains untouched. A full refresh is the migration path: it recollects the new graph, then removal-by-omission reconciles an omitted retained module exactly once through its retained reconciler. **Rationale:** a live runtime that picks up this change with `runtime/refresh!` rather than a restart can still hold declarations collected before the pickup, and their retained reconcilers must keep tearing down (SPEC-004.C46b). Allowing targeted evaluation would instead retract the old contribution before a fresh declaration could be accepted, while removing the retained-state reader in the same step would turn a supported pickup into lost teardown. **Rejected:** requiring a weaver restart to pick up the cutover or silently retracting a retained module through targeted refresh.

- **DELTA-Dsp-004.D3a (the retained reader is temporary state, and this is its removal trigger):** What D3 keeps is live-pickup state, not a second entry-point grammar that core carries indefinitely. The sole tolerance is `legacy-resolved-entry-points`, which seeds the retained resolved set from an old in-memory graph before a full refresh removes an omitted module and identifies the old declarations that targeted work must refuse; fresh normalization and entry-point resolution never consult declaration keys. **Removal trigger:** delete that reader and its targeted-refresh guard once no supported live weaver generation predates the cutover — that is, once every world that matters has restarted or been rebuilt from a graph collected after this change, so no in-memory declaration can still carry an entry point. **Not before:** until then that reader is what runs a pre-cutover module's `:removed` reconcile, and deleting it early silently drops teardown for exactly the modules the pickup was meant to protect (`PLAN-Dsp-001.R2`). A maintainer retiring the reader checks that condition, not the calendar. **Rationale:** D3 without a trigger is how a transitional accommodation becomes permanent, because the next reader has to re-derive the pickup argument before they dare touch it.
