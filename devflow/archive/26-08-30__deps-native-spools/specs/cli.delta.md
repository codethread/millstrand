# CLI delta for deps-native spool dependencies

**Document ID:** `DELTA-DnsCli-001`
**Root spec:** [cli.md](../../../specs/cli.md) (`SPEC-002`)
**Feature:** [../proposal.md](../proposal.md) (`PROP-Dns-001`)
**Status:** Proposed
**Last Updated:** 2026-08-29

This delta replaces `SPEC-002.C3`, `SPEC-002.C14a-C14b`, `SPEC-002.C16-C20`, and the dependency-launch parts of `SPEC-002.C56-C59`. It does not replace the restart lifecycle, admission, delivery, or continuity rules in `SPEC-002.C56-C59`.

## DELTA-DnsCli-001.P1 Millstrand source and workspace bootstrap

- **DELTA-DnsCli-001.CC1 (replaces SPEC-002.C3):** Mill resolves the Millstrand source checkout with the existing `--source`, environment, sibling-checkout, and built-in precedence. That source supplies one paired `io.millstrand/millstrand` coordinate as reserved launch data. Workspace dependency files cannot override or redeclare that lib. A declaration in either `deps.edn` or `deps.local.edn`, including under either selected alias, fails before resolution with `reserved dependency io.millstrand/millstrand is supplied by Mill`. Mill never persists its resolved source path in workspace configuration.
- **DELTA-DnsCli-001.CC2 (replaces SPEC-002.C14a):** `mill init` creates or completes the selected workspace without contacting a Weaver, initializing storage, or running `git init`. Its required dependency file is `<selected-workspace>/deps.edn`; when absent, bootstrap creates it as the canonical tools.deps map for the shipped workspace. Bootstrap retains `config.json`, `init.clj`, and the generated help module, removes `spools.edn` and `spools.local.edn` from the template, and does not create either personal overlay. The selected workspace's `.gitignore` ignores `config.local.json`, `deps.local.edn`, and `init.local.clj`. Existing files are never overwritten. The ordinary repository guidance behavior from `SPEC-002.C14a` remains unchanged.
- **DELTA-DnsCli-001.CC3 (replaces the bootstrap part of SPEC-002.C14b):** `mill init --stealth` uses the same `deps.edn` template and ignored personal files as CC2. Its repository selection, tracked-path refusal, exact owned marker blocks, success shape, and guidance behavior remain as specified by `SPEC-002.C14b`. Stealth mode adds no alternate dependency file or compatibility grammar.
- **DELTA-DnsCli-001.CC4 (required migration failure):** Launch requires a readable regular `<selected-workspace>/deps.edn`. If it is absent, launch fails before dependency resolution with stage `deps-read`, the resolved canonical path, and remediation to create that file. When `spools.edn` or `spools.local.edn` is also present, the remediation is exactly `dependency migration required: create <resolved-path>/deps.edn; spools.edn is no longer supported` and refers to `docs/spools/deps-migration.md`. A legacy manifest never supplies an empty, inferred, or default basis. Malformed or unreadable required data fails at the same boundary; Mill does not retry, fall back to an enclosing project or user config, or parse a compatibility grammar.

## DELTA-DnsCli-001.P2 Launch and client commands

- **DELTA-DnsCli-001.CC5 (replaces SPEC-002.C16 launch construction):** `mill weaver start` resolves the selected workspace and Millstrand source, asks the Weaver launch boundary to compose the generation basis defined by `DELTA-DnsRuntime-001.CC2-CC6`, and starts `millstrand.core.weaver.runtime` in that basis. The launch reads the required `deps.edn` and optional `deps.local.edn` once, disables the tools.deps user source, selects `:millstrand/weaver` then `:millstrand/local` when declared, and supplies the reserved runtime coordinate. It never composes an enclosing project's basis. The existing name, ready timeout, log, storage, startup-file order, and orphan-prevention contracts in `SPEC-002.C16` remain unchanged.
- **DELTA-DnsCli-001.CC6 (replaces SPEC-002.C17-C19):** `mill weaver repl`, including `--stdin`, attaches to the selected running Weaver exactly as before. The thin attach client uses Mill-resolved launch code, but forms evaluate in the running generation's single classloader and immutable basis. REPL attachment does not read dependency files or resolve a candidate basis. `mill prime millstrand` retains its existing source-resolution and output contract.
- **DELTA-DnsCli-001.CC7 (replaces SPEC-002.C20-C20b):** `mill weaver status` retains its existing health, identity, storage, log, pid, socket, and nREPL fields and adds `basis_fingerprint`, a required string when a generation is running. The value is the exact `sha256:<64 lowercase hexadecimal digits>` fingerprint published by `DELTA-DnsRuntime-001.CC6`; Mill relays it unchanged and never recomputes it. Non-running list rows do not invent a fingerprint. Running `mill weaver list` rows include the same required field. The Clojure projection is owned by `:millstrand.core.specs/mill-status-projection`; the Go status and list response structs own the JSON spelling and closed field types. The Weaver metadata decoder consults `:millstrand.core.specs/weaver-status-projection`, then Mill validates its result projection before command emission. Their owning contract-doc references are `SPEC-002.C20`, `SPEC-002.C20a`, and this clause; malformed or inconsistent data fails loudly.

## DELTA-DnsCli-001.P3 Replacement and dependency diagnostics

- **DELTA-DnsCli-001.CC8 (amends SPEC-002.C56-C57 launch boundary):** Restart retains the transition states, caller convergence, probe admission, readiness, and cutover behavior in `SPEC-002.C56-C57`. The fresh-generation probe and replacement startup each compose a new basis through `DELTA-DnsRuntime-001.CC2-CC6`, using the original selected workspace and Millstrand source as their authorities. They do not materialize approved roots or invoke the removed acquisition subsystem. A successful replacement publishes the new generation's immutable `basis_fingerprint`. A failed dependency read or resolution is a stage-specific restart failure and follows the retained rule: probe failure leaves the old generation serving; failure after cutover leaves the transition `failed` and never readmits the old generation.
- **DELTA-DnsCli-001.CC9 (dependency failure wire fields; resolves the CLI part of PROP-Dns-001.Q2):** A launch or restart dependency failure uses `diagnostics.dependency` with exactly `status`, `stage`, `source_path`, `message`, `cause`, and `coordinate`. `status` is `invalid-dependency-config`; `stage` is `deps-read` or `deps-resolve`; `source_path`, `message`, and `cause` are non-blank strings; `coordinate` is either `null` or the JSON projection of one offending tools.deps lib and its supplied coordinate value. `deps-read` names the file being parsed. `deps-resolve` names the source path whose composed value introduced the coordinate when tools.deps can isolate one; otherwise `coordinate` is `null` and `cause` preserves the original resolver cause as an explicit unresolved-coordinate outcome. The shape is owned by `:millstrand.core.specs/dependency-diagnostic` within `:millstrand.core.specs/restart-result` and `:millstrand.core.specs/mill-status-projection`; the Go wire structs own the closed JSON spelling. The launch adapter validates the Clojure diagnostic before transport, and Mill validates the decoded diagnostic before status or result emission. The owning docstring is the launch diagnostic encoder/decoder pair and its contract-doc reference is this clause. Missing required fields, unknown stages, malformed coordinates, or a discarded cause fail loudly.
- **DELTA-DnsCli-001.CC10 (retains SPEC-002.C58-C59):** The admission gate, one-send boundary, delivery evidence, interruption outcomes, and restart non-goals remain unchanged. Basis composition does not add replay, retry, fallback startup, rollback, or a second attempt under another dependency source. Custodied work and all other continuity promised by `SPEC-004.C113-C123` survive a dependency-driven replacement under the same rules.

## DELTA-DnsCli-001.P4 Removed surface and non-goals

- **DELTA-DnsCli-001.CC11:** This delta removes seeded spool manifests and their bootstrap ignore entry. It adds no public operation, option, alias, or compatibility grammar. The exact public removal inventory remains `PROP-Dns-001.S6`; this delta does not widen it.
- **DELTA-DnsCli-001.CC12:** Every filesystem dependency input is parsed once at the launch or refresh boundary. After validation, trusted interior launch and status code consumes the parsed shape without fallback or repeated defensive validation. Missing or malformed required data fails loudly. Theoretical malformed interior states add no recovery branch.

## DELTA-DnsCli-001.P5 Open questions

None. CC7 and CC9 resolve the CLI-owned fields of `PROP-Dns-001.Q2`; `DELTA-DnsRuntime-001.CC6` resolves `PROP-Dns-001.Q1`.
