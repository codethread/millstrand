## PROP-Dfr-001.P1 Problem

The workflow spool has two runtime-selected hand-offs. `defer` closes the current root and pours a selected workflow as the next root. `dispatch` pours a selected workflow below the current root, waits for it as a procedure, then resumes the declaring workflow.

`dispatch` is the behavior `defer` was meant to provide: defer target selection until a worker can choose, run the selected routine, then continue the declaring workflow. Keeping both constructs makes every author learn a root-transfer model and a second builder, ready role, worker verb, entrypoint rule, attribute family, discovery shape, and failure vocabulary. No registered workflow in this repository uses the defer root transfer.

The distinction also obscures the small composition model the spool needs:

| Construct          | Target selection | Returns |
| ------------------ | ---------------- | ------- |
| `call`             | Authoring time   | Yes     |
| `defer`            | Run time         | Yes     |
| checkpoint `:next` | Authoring time   | No      |

A defer with dependents resumes them after the selected routine. A defer without dependents is still returning composition; the declaring root closes once the selected routine and any parallel sibling work finish. Tail position must not silently change its semantics.

## PROP-Dfr-001.P2 Goals

- **PROP-Dfr-001.G1:** Give `defer` the runtime-selected returning behavior currently implemented by `dispatch`.
- **PROP-Dfr-001.G2:** Remove `dispatch` as public Clojure, CLI, graph, discovery, documentation, and failure vocabulary rather than preserving an alias.
- **PROP-Dfr-001.G3:** Keep one authority boundary: a publishing spool declares the defer point, and user code binds the registered targets it permits.
- **PROP-Dfr-001.G4:** Preserve the proven dispatch guarantees under defer names: explicit target params, live target resolution, atomic fill, retry after refusal, procedure-join completion, lexical cycle rejection, and support for empty targets.
- **PROP-Dfr-001.G5:** Make a final defer ordinary returning composition with no successor, not an implicit ownership transfer.

## PROP-Dfr-001.P3 Non-goals

- **PROP-Dfr-001.NG1:** No compatibility alias for `dispatch`, `dispatch!`, `continue!`, the CLI `dispatch` or `continue` verbs, removed roles, failure reasons, or attributes. This is a pre-v1 clean break under TEN-000@1.
- **PROP-Dfr-001.NG2:** No position-dependent mode on `defer`. Whether a defer has dependents does not choose between inline composition and root transfer.
- **PROP-Dfr-001.NG3:** No replacement runtime-selected root-transfer primitive. A real consumer may justify a plainly named transfer construct later.
- **PROP-Dfr-001.NG4:** No change to checkpoint `:next` or `:revise` routing. They remain authored root transitions and continue to support the repository's land and story workflows.
- **PROP-Dfr-001.NG5:** No data migration for already-poured workflow strands. The cutover requires zero active workflow roots, so no in-flight run crosses the contract change. Historical attribute rows remain ordinary stored data; current workflow projections stop assigning removed dispatch or continuation semantics to them.
- **PROP-Dfr-001.NG6:** No caller-context inheritance. The selected target continues to receive its own defaults plus only the params supplied when the defer is filled.

## PROP-Dfr-001.P4 Proposed scope

- **PROP-Dfr-001.S1 (authoring model):** `workflow/defer` becomes the sole runtime-selected returning declaration. It accepts the dependency and presentation options dispatch accepts today, but still rejects `:condition` and `:loop` with `:workflow/defer-not-static`. A step, checkpoint, call, condition, or loop may depend on a defer. Remove only the topology rule that forbids dependents and the rules that forbid a called or runtime-selected procedure from containing a defer; retain static-declaration validation.
- **PROP-Dfr-001.S2 (binding and entrypoints):** `bind-defers` is the single binding transformation for defer declarations, with input spec `::defer-bindings`. It binds them to non-empty sets of registered targets; remove `bind-handoffs` and `::handoff-bindings` without aliases. Each defer target must declare `:call`, because filling a defer executes it as an inline procedure that returns. Retain `:continue` only for registered workflows reached through checkpoint `:next`; the repository's land and story continuations keep that entrypoint.
- **PROP-Dfr-001.S3 (fill operation):** Add `defer!`, the worker-tier `run-defer!`, and the CLI `workflow defer` verb as the only operations that fill a ready defer. Remove `continue!`, `run-continue!`, and the CLI `workflow continue` verb. `defer!` resolves one allowed target live, validates only that target's defaults plus explicit params, pours the target below the current root, and rewrites the defer into an ordinary procedure join in one batch. It then resumes the declaring workflow when the join closes. `run-defer!` owns the validated `::defer-request` worker boundary, ready-role inference, and the retained `ready-defer-*` refusal family used by the CLI handler.
- **PROP-Dfr-001.S4 (tail behavior):** A defer may be the final declared step. After its selected routine exits, the join closes normally. The run becomes done only when every workflow work strand under the declaring root is closed, so parallel siblings are never abandoned by filling a final defer. An empty or fully conditioned-out target closes the join in the fill batch.
- **PROP-Dfr-001.S5 (identity and cycles):** Nested-defer cycle safety is new behavior. Compiling a root initializes its ancestry with that definition's fingerprint. A fixed call appends the callee fingerprint while compiling its expansion, and filling a defer appends the selected target fingerprint while compiling that expansion. The compiler unconditionally overwrites every defer's authored path with the resulting engine-owned `workflow/defer-path`; raw definition maps cannot bypass the stamp. Definition validation also rejects authored values with `:workflow/defer-path-reserved`, and malformed persisted engine values fail with `:workflow/defer-path-invalid`. Before mutation, a fill rejects a target already present in the current path with `:workflow/defer-cyclic`; therefore `A → B → A` fails at the second fill. Remove all three existing `require-no-defers!` enforcement sites in definition validation, fixed-call compilation, and deferred-fill routing, then remove the helper and replace the dispatch-only stamping and checks. Tests cover raw-path forgery through the builder, a raw definition map compiled with an authored path, direct self-selection, cycles through fixed calls, cycles through successive defers, and acyclic nesting.
- **PROP-Dfr-001.S6 (durable graph and history vocabulary):** The declaration marker is `workflow/defer`, its target allowlist is `workflow/defer-workflows`, its engine ancestry is `workflow/defer-path`, and its pending `workflow/role` is `"defer"`. Remove `workflow/dispatch`, `workflow/dispatch-workflows`, and role `"dispatch"`. Discovery keeps one `:defers` collection whose entries include `:entrypoint "call"` and removes `:dispatches`. The filled procedure join records the selected name, resolved definition, fingerprint, exact target params, and optional fill actor as `workflow/deferred-workflow`, `workflow/deferred-definition`, `workflow/deferred-fingerprint`, `workflow/deferred-params`, and `workflow/deferred-by`. Add `workflow/defer-path` and every `workflow/deferred-*` key to the workflow vocabulary seed. Its `workflow/procedure` value remains the defer strand id. Procedure auto-close may stamp `workflow/outcome-by "engine"` independently; that does not replace the fill actor. Remove both `workflow/dispatched-*` and `workflow/continued-*`. A filled defer remains procedure bookkeeping, does not set `workflow/outcome`, and does not become a continuation event or a separate history molecule. Remove `:continuation` from the `run-history` event type contract and remove role `"defer"` from history-event eligibility; both filled joins and unfilled defers force-closed by a checkpoint cutover are omitted. Runtime selection remains available through full strand reads, not `run-history`.
- **PROP-Dfr-001.S7 (deleted transfer semantics):** Remove the defer cutover that closes the old root, pours a new root, replaces `workflow/context`, abandons active sibling work, and records a continuation event. Runtime-selected composition stays within one molecule and keeps the declaring root as the run's current root.
- **PROP-Dfr-001.S8 (surface removal and failures):** Remove the `dispatch` builder, `dispatch!`, `run-dispatch!`, CLI `dispatch` verb, dispatch request/result specs, ready-role branches, attention reason, discovery projection, explain topic, durable vocabulary declarations, and generated API entries. Remove the old root-transfer `continue!` and `run-continue!` surface and its transfer-only reasons at the same cutover. Add `run-defer!` and `::defer-request` as the worker-tier successor. Rename `dispatch-cyclic`, `dispatch-path-invalid`, and `dispatch-path-reserved` to new `defer-cyclic`, `defer-path-invalid`, and `defer-path-reserved` reasons. Merge `dispatch-target-not-allowed`, `dispatch-not-ready`, `step-not-dispatch`, and the `ready-dispatch-*` family into `defer-target-not-allowed`, `defer-not-ready`, `step-not-defer`, and `ready-defer-*`. `bind-defers` reports an unknown declaration as `defer-unknown`, replacing `handoff-unknown`. Retain the pending-defer reasons that still describe the new construct, including `defer-unbound`, `defer-not-static`, and `step-is-defer`; remove obsolete `defer-not-terminal`, `defer-in-procedure`, remaining `handoff-*`, and root-transfer-only reasons. No removed reason remains as an alias.
- **PROP-Dfr-001.S9 (contracts and guidance):** Update the workflow contract, cookbook, README, generated API docs, discovery `prime`/`about` text, shared-spool guidance, source docstring citations, and Ubiquitous Language. Add a release runbook that makes the cold-cutover sequence and the prohibition on live refresh impossible to miss at pickup time. Mark `RFC-Dyc-001` and the affected defer/`continue!` points of `PROP-Wcd-001` superseded by this decision; repoint live source citations, including references to `DELTA-Dyc-001`, to the applicable `PROP-Dfr-001` points. Archive the dispatch delta as historical rather than current authority. Remove the adapter recipe whose terminal-defer mechanism no longer exists; replace it with middle-position and final-position defer examples.
- **PROP-Dfr-001.S10 (consumer cutover):** Audit direct readers of workflow roles, failure reasons, declaration and allowlist attributes, `workflow/continued-*`, `workflow/dispatched-*`, `workflow/outcome`, discovery keys, `run-history`, and `current-root`, not only callers of the public functions. Include the repository's `.millstrand` coordination configuration and its worker-surface prose in the coordinated operator edit. The pre-implementation audit checked the exact pinned sources for agent-harness v15 (`0e3f43f…`), devflow v9 (`499c9d6c…`), and kanban v11 (`e165b9b8…`); none reads or calls the removed workflow surface. No peer successor or pin movement is required, and the feature adds no Alpha Surface exception. The coordinated release is a clean break with no compatibility shim.
- **PROP-Dfr-001.S11 (pending and fill invariants):** An unfilled defer is a ready workflow-work role distinct from `procedure`; it blocks done, cannot be closed by `complete!` or `advance!`, and is not eligible for procedure cascade. Filling it atomically prefixes every expansion ref with the defer id, parents every expansion strand beneath the current root, carries the defer's incoming dependencies onto target entries, rewrites the defer as a procedure join, and makes that join depend on every target exit. Procedure cascade remains procedure-only. A checkpoint `:next` or `:revise` cutover force-closes any sibling unfilled defer with the rest of the abandoned root.
- **PROP-Dfr-001.S12 (coordinated cutover):** Zero live roots is a release precondition, not a permanent runtime feature. Before installing the breaking build, the operator quiesces every workflow producer and worker for each consuming workspace, including direct in-process callers, so no mutation can race the check. In this repository the proof is an empty `strand workflow-runs`; other consumers call `workflow/active-runs` through their existing operator surface or the release preflight. Any workflow run is finished or explicitly abandoned, and any bare root or wisp is burned or squashed. The user authorizes stopping the canonical weaver only after that proof.

    The contract change is never picked up through live refresh. With producers still quiesced and the old weaver stopped, the operator installs the repository build and starts the new weaver. The audited peer pins remain unchanged. Producers resume only after startup and smoke checks succeed. This feature adds no compatibility alias, data migration, schema table, module grammar, admission lock, rollback path, or old-strand detector for the one-time cutover. If the release precondition is violated, behavior for an old strand under the new engine is undefined under TEN-000@1; no recovery or reinterpretation guarantee is made.

## PROP-Dfr-001.P5 Open questions

- **PROP-Dfr-001.Q1 (answered):** No current in-repo workflow requires runtime-selected root transfer, and the exact pinned peer sources do not consume the removed surface. The operator runbook requires every producer quiesced and every active-root query empty before the old weaver stops. A future consumer with a concrete transfer requirement may propose a separately named construct.
- **PROP-Dfr-001.Q2 (answered):** `bind-defers` replaces `bind-handoffs`, restoring the original defer-specific name from `PROP-Wcd-001.S7` with the new returning semantics. It names the declaration being bound and leaves no parallel handoff vocabulary.
