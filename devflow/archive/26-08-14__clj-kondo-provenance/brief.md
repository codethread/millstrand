# Brief: clj-kondo hook provenance and repository hygiene (`e44fr`)

Card `e44fr`, corrective work beneath epic `d8yjf`. The user approved the full five-repository scope. This work must not create a Millstrand `v1` marker.

## Problem

The first `d8yjf` rollout copied Millstrand's published clj-kondo config into consumers, but import presence did not guarantee import ownership. A producer export is the configuration published beside the macros it models; a consumer import is the reviewed snapshot copied from a resolved dependency. Millhouse imports the canonical six Millstrand authoring hooks and then overrides every mapping with older functions in its root project hook file. Millhouse also redefines the Workflow root's own `defworkflow` and `defexecutor` analysis instead of consuming the export that the Workflow root publishes.

The same ownership error appears in the opposite direction. Millstrand and Agent Harness model Millhouse Workflow forms locally instead of consuming the Workflow export. Millstrand also carries obsolete mappings for pre-Millhouse namespaces. These local rules can drift while lint still passes.

Repository hygiene has a separate defect. Notebook and Standup commit clj-kondo cache files. Millhouse currently has two untracked self-import files that are byte-identical to its Workflow export and were generated by the consumer import flow. A successful lint or copy-config run must leave the repository clean and must not turn transient cache state into source.

## Decision

Each public macro surface has one producer-owned clj-kondo export. External consumers keep reviewed snapshots under `.clj-kondo/imports`; they do not remap the same symbols in root config or duplicate producer hook functions. A producer consumes its own export directly through `:config-paths`, avoiding a second checked-in copy of its own files.

Checked-in external snapshots make a dependency change visible as a consumer review diff. Direct self-consumption avoids a second producer copy that could drift from the export.

Apply that rule in Millhouse, Millstrand, and Agent Harness. Keep repository-only policy hooks local. Remove obsolete mappings that have no current source use. Remove tracked cache artifacts from Notebook and Standup and add ignore coverage at each affected root.

Update the Millhouse `publish-spool-kondo` and `bump-spool` workflows so future work checks producer ownership, imported snapshot drift, local overrides, cache artifacts, and final Git cleanliness. The guardrails must describe and test the same ownership model used by the repaired repositories.

## Scope

- Millhouse: retain the canonical Millstrand import; remove local implementations and mappings for Millstrand-owned forms; consume Workflow, Chime, and Cron self-owned exports from their producer resource directories where applicable; retain only Millhouse repository policy hooks; ensure the known generated Workflow self-import copies do not remain; update workflow definitions, tests, and public workflow documentation.
- Millstrand: consume the pinned Millhouse Workflow export; remove local `defworkflow`, `defexecutor`, and obsolete pre-Millhouse rule shims; keep Millstrand's own export wired through its producer resource directory; update import proof or lint checks as needed. Do not create a `v1` marker.
- Agent Harness: import the pinned Millhouse Workflow export and remove its local `defexecutor` approximation and exclusion; preserve its own producer export and existing Millstrand import.
- Notebook and Standup: remove tracked `.clj-kondo/.cache` files, add ignore coverage, and prove the normal quality command does not recreate tracked or untracked repository dirt.
- Coordination: land producer changes before consumers that need a new pin, refresh generated external imports once from the resolved classpath, inspect each generated diff, and leave every in-scope repository Git-clean.

## Done when

- No consumer-local config or hook function redefines a public macro covered by a resolved producer export.
- Every external import snapshot used by the affected repositories matches its pinned producer export byte for byte.
- Producers consume their own exports directly and do not check in redundant self-import copies.
- No tracked clj-kondo cache remains in Notebook or Standup, and ignore rules prevent recurrence.
- The publish and bump workflows carry executable or test-backed checks for provenance, drift, cache state, and final cleanliness.
- Each repository's documented lint and quality boundary passes from its task worktree, followed by a clean `git status --short`.
- Changes are committed, reviewed, landed in dependency order, and adopted by downstream pins where the producer commit changes.
