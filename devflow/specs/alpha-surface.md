# Alpha Surface

**Document ID:** `SPEC-005` **Status:** Implemented **Last Updated:** 2026-09-01 **Related:** [Strand Model](./strand-model.md), [CLI Surface](./cli.md), [REPL API](./repl-api.md), [Weaver Runtime](./daemon-runtime.md), [Spools index](../../spools/README.md), [Writing shared spools](../../docs/spools/writing-shared-spools.md)

## SPEC-005.P1 Purpose

This spec draws the line around what Millstrand ships as "alpha": which surface is in-contract (and where each contract lives), and which surface is explicitly internal. It is a contract index — it adds no behavior. The rule is exclusionary: surface not reachable through the in-contract tiers below is internal, regardless of Clojure var visibility or OS observability. TEN-000@1 still applies to everything: in-contract alpha surface evolves by accretion within a tier's own compatibility discipline, and internal surface may change without notice.

## SPEC-005.P2 In-contract surface

- **SPEC-005.C1:** The behavior contracts for shipped engine surface live in SPEC-001 through SPEC-004, as linked above.
- **SPEC-005.C2:** The blessed spool-facing API is every `millstrand.api.*.alpha` namespace. The current 26 are `millstrand.api.authoring.alpha`, `millstrand.api.batch.alpha`, `millstrand.api.cli.alpha`, `millstrand.api.clock.alpha`, `millstrand.api.current.alpha`, `millstrand.api.errors.alpha`, `millstrand.api.events.alpha`, `millstrand.api.format.alpha`, `millstrand.api.graph.alpha`, `millstrand.api.hooks.alpha`, `millstrand.api.lifecycle.alpha`, `millstrand.api.millstrand.alpha`, `millstrand.api.notes.alpha`, `millstrand.api.patterns.alpha`, `millstrand.api.peers.alpha`, `millstrand.api.process.alpha`, `millstrand.api.registry.alpha`, `millstrand.api.relations.alpha`, `millstrand.api.return-shape.alpha`, `millstrand.api.runtime.alpha`, `millstrand.api.runtime.glossary.alpha`, `millstrand.api.runtime.help-transform.alpha`, `millstrand.api.scheduler.alpha`, `millstrand.api.spec.alpha`, `millstrand.api.spool.alpha`, and `millstrand.api.weaver.alpha`. `millstrand.test.alpha` is the separate author-side test tier; `millstrand.repl` is the separate human-facing helper tier. Source, generated [API docs](../../docs/api/README.md), and tests define the vars within these namespaces; their behavior contracts live in SPEC-001, SPEC-003, and SPEC-004.
- **SPEC-005.C3:** The shipped reference-spool tier is exactly `millstrand.spools.*`, currently `batteries` and `unsafe-text-search`, with contracts in [`spools/*.md`](../../spools/README.md). A dependency makes a spool available but never activates it; activation is always an explicit declaration in `init.clj` or `init.local.clj`. `mill init` seeds both the Batteries dependency and its shared activation, either of which may be removed to opt out. Activated spools use the running generation's tools.deps basis and classloader.
- **SPEC-005.C4:** Every spool outside `millstrand.spools.*` is userland, including externally distributed domain spools and workspace spools. Its own documentation defines its contract and release cadence.
- **SPEC-005.C10:** The frozen trained-vocabulary tokens are the published command and subcommand names under `strand agent`, the `agent-plan` pattern name, the `agent-failures` query name, and the `:subagent` waiter value. This clause freezes only those tokens. It does not freeze their flags, input fields, return keys, attribute keys, or backing Clojure function names; those follow C11.
- **SPEC-005.C11:** Spool vocabulary is inheritance-first. A spool that invokes a primitive or reproduces its concept uses that primitive's published vocabulary and mints names only for new concepts. [Writing shared spools](../../docs/spools/writing-shared-spools.md#the-rules-for-shared-spools) owns the detailed test, examples, peer rules, and review guidance. Only this spec may freeze a name; C10 is the current complete freeze list.
- **SPEC-005.C12 (core authoring families):** `millstrand.api.millstrand.alpha` publishes three forms for each core kind: an inert `def<kind>` definition, a typed `use-<kind>!` selection, and a `def<kind>!` definition-and-selection shorthand. The six kinds are `op`, `query`, `pattern`, `hook`, `handler`, and `bin`. `defbin` is the public definition form for core `:bins`; its option grammar and declaration constructor remain internal. SPEC-004.C63h/C63i own the effective registry, read protocol, and consulted internal bin result specs.
- **SPEC-005.C13:** `millstrand.api.authoring.alpha` owns the protocol-1 declaration descriptor and the `defauthoring` family generator. Generated macros are public surface of their defining domain namespace, not Millstrand re-exports. The core and lifecycle families expose inert definition, typed selection, and definition-and-selection forms; function-backed forms bind the exact authored name. The external acceptance script owns its dependency pin and verifies publication against a disposable source and retained image.

## SPEC-005.P3 Explicitly internal

- **SPEC-005.C5:** `millstrand.core.*` is internal and may change freely (public vars included); trusted code that requires it accepts the compatibility cost (SPEC-004.C40).
- **SPEC-005.C5b:** All non-alpha `millstrand.api.*` implementation plumbing is internal, including `.internal` namespaces and singular internal modules such as `millstrand.api.process.internal`. Only a sibling `.alpha` module may expose behavior from this plumbing as contract (SPEC-003.C19a); its public vars may change freely.
- **SPEC-005.C5a:** Deterministic time is in-contract through the blessed tiers in C2: `millstrand.api.clock.alpha` owns the Clock abstraction, `millstrand.api.runtime.alpha/clock` and `now` expose the runtime Clock and its data-first read, and `millstrand.test.alpha/manual-clock`, `set-clock!`, and `advance!` are author-side controls (SPEC-004.C1a, SPEC-003.C17a/C28a). The runtime-map `:clock` slot and clock-pump registry remain internal core plumbing.
- **SPEC-005.C6:** The mill JSON socket protocol is internal transport glue. SPEC-002 owns the CLI contract and SPEC-004.C9a owns published artifact locations; socket frames, operations, error codes, protocol version, and `mill.json` fields are outside both contracts.
- **SPEC-005.C7:** On the weaver socket, the error `type` taxonomy and envelope shape are contract (SPEC-004.C24); concrete error `code` strings are contract only where individually specified (`operation/deadline-exceeded` SPEC-004.C26b, `query/not-found` SPEC-004.C36b, `hook/failed` SPEC-004.C84). Other code strings, and all human-readable message text, may change.
- **SPEC-005.C8:** Generated-file contents, client transport timeouts, storage mechanics, and plain or pretty stderr rendering are internal except where SPEC-001 or SPEC-002 specifies behavior. SPEC-002.C4e owns the `MILLSTRAND_ERROR_FORMAT=json` envelope; C7 governs its code strings.

## SPEC-005.P4 Change discipline

- **SPEC-005.C9:** A change across this boundary updates its owning spec or spool doc. Update this index when tier membership changes.
- **SPEC-005.C9a:** Deprecation in a `millstrand.api.*.alpha` namespace is advisory metadata: `{:deprecated true :since "vN" :replacement fully-qualified-symbol}`. It does not itself make an accepted call fail or prevent an intentional removal under TEN-000@1. The first use of this metadata must expose it in the generated API docs.
- **SPEC-005.C9c:** Core and lifecycle authoring families retain the forms and exact-name rules in C12/C13. Owner-complete publication and omission retraction are owned by SPEC-003.C25b/C25c and SPEC-004.
